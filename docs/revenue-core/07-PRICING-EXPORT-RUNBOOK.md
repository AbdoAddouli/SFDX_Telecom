# Pricing export and rollback runbook

> **Scope:** the custom Revenue Core pricing metadata (`Pricing_Procedure__mdt`,
> `Pricing_Rule__mdt`, `Config_Rule__mdt`). This is the replacement for RCA
> decision-table export. The org has no Revenue Cloud licence.

## Artefacts

| Path | Purpose | Deployable |
|---|---|---|
| `pricing-export/procedures/*.json` | Grouped pricing procedures | No (audit view) |
| `pricing-export/rules/*.json` | One file per pricing rule | No (audit view) |
| `pricing-export/config-rules/*.json` | One file per configuration rule | No (audit view) |
| `pricing-export/manifest.json` | SHA-256 for every JSON file, totals | No |
| `pricing-export/rollback/customMetadata/*.md-meta.xml` | Snapshot of the 10 source-controlled records | **Yes** |
| `pricing-export/rollback/manifest.json` | SHA-256 for the rollback XML files | No |

The JSON files are the human-readable audit view. The XML snapshot is the
deployable rollback artefact. Both are regenerated by one export run.

## Export

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\export-pricing.ps1 -TargetOrg abdo@telecom.com
```

The script:

1. Queries the three custom metadata types with `sf data query`.
2. Rebuilds `pricing-export/` from scratch (the folder is overwritten).
3. Writes one JSON file per procedure, pricing rule, and configuration rule.
4. Computes the SHA-256 manifest for the JSON files.
5. Copies the 10 matching source XML files into `pricing-export/rollback/`.
6. Computes a second SHA-256 manifest for the rollback files.

`scripts/export-pricing.apex` produces the same JSON layout as a zip and emails
it; use it when the release needs an org-side export without local file access.

## Verify

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-pricing-export.ps1
```

The verifier needs no org connection. It checks:

- Both manifests use SHA-256 and their per-file hashes match.
- `totals.files` and `totals.records` match the manifest contents.
- No JSON file exists outside the manifest.
- The rollback manifest contains exactly the records referenced by the export
  JSON (procedures, pricing rules, configuration rules).
- The export and rollback timestamps match.

It exits non-zero on the first mismatch. For CI, make this a required step after
the export artefact is available:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-pricing-export.ps1
```

The verifier checks artefact integrity, not org/source drift. Re-run the export
immediately before verification when the release must reflect the live org.

## Rollback

Preview the deployment:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-pricing.ps1 -DryRun
```

Apply the snapshot:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-pricing.ps1
```

The script verifies every rollback hash, copies the XML outside the
`.forceignore`-excluded `pricing-export/` tree into a transient
`pricing-restore-<guid>/customMetadata` folder, deploys it, and removes the
transient folder in a `finally` block. It treats `NothingToDeploy` as success.

## Drill evidence (2026-11-08)

1. Baseline: Samsung S22 list price 449.00; `Device_Bundle_30_Percent` gives a
   final price of 314.30.
2. Temporary change: deployed a scratch copy of the rule with
   `Adjustment_Value__c = 25`; final price changed to 336.75.
3. Rollback: `scripts/restore-pricing.ps1` deployed the 30% snapshot; final price
   returned to 314.30.
4. Post-drill catalogue smoke: 4 mobile plans, 2 fibre plans, 3 devices; Mobile
   20 GB at `COMMIT12` = 13.49; `75001` = 2 fibre speeds; `59000` = 0; S22
   = 1 `NOCOMMIT` block and 0 at `COMMIT12`.

## Refresh discipline

After any `PricebookEntry` change, re-run the export and verification before the
release. A stale export silently reproduces the old price (`ARCHITECTURE.md`
anti-pattern §15).

## Version control

`pricing-export/**` is excluded by `.forceignore` and is currently untracked.
The deployable source remains `force-app/main/default/customMetadata`. Commit or
archive the export folder only when the release owner explicitly requests it.
